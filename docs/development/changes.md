# Change routes

Use the route that matches the behavior being changed. [Architecture](architecture.md) explains ownership; [workflows](workflows.md#prerequisites-and-setup) owns prerequisites and the [command catalog](workflows.md#tests-and-checks). Public option meanings belong in the [API](../reference/api.md), [CLI](../reference/cli.md), and [Vite](../reference/vite.md) references, not in this guide.

The proof selections below are deliberately narrow. A source import sees TypeScript edits directly; a `dist/` import needs rebuilt JavaScript. Neither distinction tells you whether the selected case invokes native code or Closure: those prerequisites are called out separately. Use the [build lanes](workflows.md#build-lanes) to prepare only the artifacts that case consumes.

## Public options, CLI and Vite exposure, and cache identities

### Follow the value to its consumer

1. Start with [`src/api/types.ts`](../../src/api/types.ts): public types, accepted-value constants, resolved fields, and defaults live together. Its published docstrings are part of the contract. [`normalizeBuildOptions`](../../src/build/resolve/options.ts) performs runtime choice validation, path resolution, and chunk-output/vendor gates; adding a type field alone does not carry a value through this boundary. Internal-only fields belong in [`src/build/types.ts`](../../src/build/types.ts), not automatically in the public API.
2. For a CLI exposure, follow [`parseCliArgs`](../../src/cli/parse/options.ts) through [`src/cli/run.ts`](../../src/cli/run.ts) into the API. Extern generation has its own [`parseExternsCliArgs`](../../src/cli/parse/externs.ts); [`parseCleanCacheCliArgs`](../../src/cli/parse/clean-cache.ts) accepts only project/cache roots and help, not build flags or positional arguments. `runCli` has one failure-to-exit-status boundary for all commands. Update [`src/cli/usage.ts`](../../src/cli/usage.ts) as executable help, not merely the reference page. Repeated flags, invalid choices, and omitted values are parser behavior.
3. For Vite, check the exclusions and docstrings in [`src/vite/types.ts`](../../src/vite/types.ts) before exposing a core field. [`createCompilerOptions`](../../src/vite/config.ts) spreads caller options and then replaces the fields Vite owns. [`src/vite/plugin-compile/compile.ts`](../../src/vite/plugin-compile/compile.ts) adds the captured chunk graph and sidecars before calling the core pipeline. A field accepted by the type but overwritten here is not an implemented exposure. In particular, Vite derives output language from `build.target` and owns its chunk graph.
4. Continue beyond normalization: [`resolveBuild`](../../src/build/resolve/index.ts) passes graph-affecting options to native resolution/planning; [`runNativeTranspile`](../../src/build/transpile/emit-native/transpile.ts) passes transform options to the native adapter; [`prepareClosureStageJobs`](../../src/build/closure/run-closure/prepare.ts) passes compiler/job options to native job preparation. If the option reaches native code, follow the ABI route below rather than assuming the TypeScript object crosses unchanged.

### Keep behavior and identity together

[`createBuildContext`](../../src/build/resolve/index.ts) computes [`getOptionsSignature`](../../src/build/resolve/signatures.ts), which participates in native/final cache identities. Resolution reparses config and rebuilds the native graph and chunk plan every invocation; no resolve snapshot or final-fast return survives. The final key uses the fresh graph's native file hashes, inherited configuration, ambient declarations and content state. TSX runtime graph hashes and snapshots of extra authored inputs complete that identity; graph serialization is not an additional cache input. File membership/path identity and file contents are separate: `hashExternalInputs` hashes explicit externs, typed externs, and extra JS inputs; tracked files and type-metadata dependencies cover other inputs. Preserve project-relative identity when absolute relocation cannot affect output, but retain relationships that affect bytes, such as an `outFile` destination relative to `outDir`. `DEFAULT_BUILD_OPTIONS` must normalize like omitted options, including explicit `auto` values; copying the exported defaults must not select another behavior.

The core signature is not the only key. For adapter changes, inspect [`resolveViteCaptureRootPath`](../../src/vite/capture/index.ts) and the affected [prebundle cache](../../src/vite/prebundle) in addition to the core signature. For new Closure flags, follow [`compiler/environment-resolve.ts`](../../src/build/closure/compiler/environment-resolve.ts) through [`runPreparedClosureJob`](../../src/build/closure/compile-jobs/index.ts) into [`closure/cache.ts`](../../src/build/closure/cache.ts): effective environment options and renaming-map inputs affect job reuse. Each effective attempt prepares one cache key; retries prepare a fresh key. Persistence compares current input hashes with that attempt's snapshot and skips storage if inputs changed, while restoration separately verifies artifact digests. A warm cache replay can otherwise hide a correctly implemented new option.

### Select the proof

- Parser change: [`test/cli/args.test.mjs`](../../test/cli/args.test.mjs), especially `parses repeated typed build options` or `rejects invalid option values during parsing`. These import source; no package rebuild, native addon, or compiler execution is needed for these cases.
- Identity change: in [`test/build/cache-correctness.test.mjs`](../../test/build/cache-correctness.test.mjs), select `output behavior participates in the options signature`, `options signature is independent of the absolute project root`, or `Closure job cache keys and validates effective behavior`, according to the changed layer. These cases use source and filesystem fixtures, not a real native/Closure build. The file also contains real-build cases; running the whole file has different prerequisites.
- A new output-affecting option needs a consumer proof, not only a signature comparison: use one disposable project, build with a persistent cache, change only the option, and execute or inspect the changed output; repeat unchanged and then with cache off. The existing `compat changes invalidate native and final cache restores` case in [`test/build/cache-safety.test.mjs`](../../test/build/cache-safety.test.mjs) is the concrete pattern. It imports `dist/` and runs native plus Closure. For an adapter-owned value, exercise an actual Vite build; `gccTsBundler rejects compiler.languageOut in Vite mode with an actionable error` in [`test/vite/plugin.test.mjs`](../../test/vite/plugin.test.mjs) demonstrates that public guard through the built plugin.

Update the chosen surface's types, runtime normalization/parser/adapter, actual consumer, relevant keys, published source docstrings/help, and corresponding reference together. If adding a published entry point or runtime artifact, follow [`getPackageSignature`](../../src/build/resolve/signatures.ts), [`package.json`](../../package.json) exports/files, and [`scripts/build-js.mjs`](../../scripts/build-js.mjs). Package identity hashes deterministic relative paths, contents and membership of owned `.js`/`.mjs`/`.cjs` files under `bin`, `dist`, `closure-lib` and `closure-externs`, plus package metadata and the optional local addon. Stable entry facades must not hide changed shared/preserved implementation. Dependency trees are not traversed; absent artifact roots are valid during source/bootstrap work. `package identity tracks implementation bytes and JavaScript membership behind unchanged facades` in [`test/build/cache-correctness.test.mjs`](../../test/build/cache-correctness.test.mjs) defends this boundary without a real build.

## Externs and property preservation

### Keep the two extern channels separate

1. [`generateExterns`](../../src/externs/generate/generate.ts) resolves declaration/runtime inputs, creates an analysis context, renders barriers through [`render.ts`](../../src/externs/render.ts), and renders external declarations through [`typed-render`](../../src/externs/typed-render). Its `renameBarriers` and `typedDeclarations` are different artifacts, not interchangeable names for one file. Generation options and their docstrings live in [`generate/options.ts`](../../src/externs/generate/options.ts).
2. Core `externs` paths enter both native preservation and Closure. Core `typedExterns` enter Closure only. Trace native input from [`emit-native/transpile.ts`](../../src/build/transpile/emit-native/transpile.ts) through [`src/native/load/transpile.ts`](../../src/native/load/transpile.ts) into [`native/src/transpile/externs/analysis.rs`](../../native/src/transpile/externs/analysis.rs): `merge_extern_property_facts` adds explicit extern names to the preserved set. [`externs/render.rs`](../../native/src/transpile/externs/render.rs) renders generated pins. [`run-closure/prepare.ts`](../../src/build/closure/run-closure/prepare.ts) separately supplies explicit, generated typed, and native extern paths to job preparation.
3. Automatically resolved external modules also pass through [`build-plan/external-plan.ts`](../../src/externs/build-plan/external-plan.ts). The pipeline derives typed/opaque external boundaries before emission, renders one typed batch, then assembles exact typed declarations for emitted preserved imports into invocation scratch. Native cached externs are immutable inputs: never append into that artifact. [`create-type-world.ts`](../../src/externs/build-plan/create-type-world.ts) loads compiler options/declaration roots once and builds a program only when typed externs, missing sidecar analysis or Node ambients need it. Emit inputs, TSX support, authored files and transitive declarations remain protected even without a program; [`generate.ts`](../../src/externs/generate/generate.ts) resolves typed declaration seeds before constructing its analysis program. Do not repair a missing external type by placing all typed declarations in the native barrier input. Missing required extern files fail closed; automatic unresolved external types are a distinct opaque-fallback policy.
4. Vite resolves these channels in [`resolveCompilerExterns`](../../src/vite/compiler-externs/index.ts), called by [`plugin-graph/prepare.ts`](../../src/vite/plugin-graph/prepare.ts) **after dependency prebundling settles**. All extern modes use that runtime graph, not the prebundle provenance graph. [`plugin-compile/compile.ts`](../../src/vite/plugin-compile/compile.ts) feeds `renameBarriers` and `typedDeclarations` separately into `createCompilerOptions`. Explicit compiler externs are retained in that union. The generator rejects Vite external-runtime declarations when the required runtime bridge is absent; typed declarations alone do not supply runtime code.

### Decide which boundary needs protection

For a property renamed across a runtime boundary, start at the evidence owner, not at a global list of names. Native [`compat_properties.rs`](../../native/src/transpile/compat_properties.rs), [`externs/analysis.rs`](../../native/src/transpile/externs/analysis.rs), and [`emit.rs`](../../native/src/transpile/emit.rs) feed preservation/quoting and generated externs; framework call rules originate in [`src/presets`](../../src/presets). Protecting a property on one side while renaming the other breaks runtime reads; pinning every same-spelled property also imposes a whole-job cost.

[`property-policy.ts`](../../src/externs/property-policy.ts) is a caller assertion that selected structural `Object.prototype.*` barriers may be removed. It does not prove safety, remove typed owner-qualified pins, or admit unmatched names or the `__gcc*` protocol namespace. Changes here belong with the generation result and API explanation, not a promise that the resulting properties will all rename.

For false ambient/global evidence, start at [`isValueIdentifier`](../../src/shared/typescript.ts) and [`external-ownership/global-protocol.ts`](../../src/build/transpile/type-metadata/metadata/external-ownership/global-protocol.ts). Accessor names and binding-element name/property-name slots are declarations or keys, not bare reads; computed names and default initializers can still contain real reads. Optional bare globals must not blanket-protect every same-spelled property on unrelated local receivers. `classifies optional bare global protocols without a producer` in [`test/vite/type-metadata.test.mjs`](../../test/vite/type-metadata.test.mjs) exercises source evidence classification; emitted property behavior still needs the runtime route below.

Module preservation is a different route: [`native/src/graph/resolve.rs`](../../native/src/graph/resolve.rs) requires configured seeds to be reachable, promotes their static dependency closure, and rejects dynamic imports targeting the preserved set. This is not a single-file optimization toggle. [`emit-preserved-modules`](../../src/build/closure/emit-preserved-modules) publishes those modules separately; do not bypass these graph constraints to fix a property problem. See [external boundaries](architecture.md#external-boundaries-and-compilation).

### Select the proof

- Structural override: the `generateExterns propertyPolicy` cases in [`test/externs/generate.test.mjs`](../../test/externs/generate.test.mjs) cover removal, unmatched-name rejection, and protocol-name rejection. Those cases call the source generator and do not invoke native or Closure. The file also statically imports `dist/index.mjs`, so built output must exist even when filtering to these source cases; rebuild it only if selecting the dist-backed cases to observe an implementation edit.
- Declaration syntax/assembly: `typed extern signatures use parse-safe positional parameter names` and `one typed batch assembles usable boundaries without mutating native externs` in [`test/externs/typed.test.mjs`](../../test/externs/typed.test.mjs) use source and real Closure. The assembly case preserves unrelated native property carriers and executes compiled typed boundaries, not just compares generated text. It needs the [compiler prerequisites](workflows.md#prerequisites-and-setup), not regenerated `dist/` for that source edit.
- Ambient roots: `ambient declarations reach the checker through tsconfig parity, not the import graph` in [`test/build/type-metadata.test.mjs`](../../test/build/type-metadata.test.mjs) exercises source analysis. `actual builds include unimported tsconfig ambient declaration roots` in [`test/build/type-architecture-e2e.test.mjs`](../../test/build/type-architecture-e2e.test.mjs) exercises compilation and runtime behavior; it requires native and Closure. The former alone does not prove the emitted runtime boundary.
- Runtime property behavior: `string element access keeps dot-defined object literal keys resolvable` in [`test/build/property-preservation.test.mjs`](../../test/build/property-preservation.test.mjs) executes emitted code and checks both quoted and dynamic reads. It imports `dist/`, requiring rebuilt output, native, and Closure. For a Vite channel change, select `Vite routes typed extern declarations to Closure but not native preservation` in [`test/vite/plugin.test.mjs`](../../test/vite/plugin.test.mjs); this runs the built plugin with native and Closure, despite the file's source-level helper imports.

Update evidence collection, artifact routing, renderer and consumer together only where affected; carry new native fields through both ABI sides. Update generation/build/Vite docstrings and the affected [API](../reference/api.md) or [Vite](../reference/vite.md) contract. An extern-generation output comparison alone does not prove an optimized application still works.

## Output publication, cache restoration, and error cleanup

### Follow the commit boundary, not just the compiler result

[`src/build/pipeline.ts`](../../src/build/pipeline.ts) owns the invocation and its `CacheStore` before calling resolution. After the fresh graph/config/chunk plan, [`pipeline/setup.ts`](../../src/build/pipeline/setup.ts) tries final-cache restore before emission. On a miss, the pipeline creates [`invocation staging`](../../src/build/cache/final/staging.ts) for output and compiler/cache work, assembles externs alongside raw job inputs, and compiles into those existing trees without deleting/recreating them. It then calls `finalizePipelineBuild`, which prepares the canonical final manifest only in persistent mode before publication; destination mappings and relocated bytes are also prepared before the first public-directory replacement.

[`cache/final/publish.ts`](../../src/build/cache/final/publish.ts) is the owner to change for publication and restoration:

- `publishStagedClosureResult` validates cache mappings and prepares destination files, then commits the cache directory, `outDir`, and external files separately. The rename/backup helper handles one directory at a time; later failures can follow earlier successful commits.
- `restoreCachedBuild` validates one final manifest's key, signatures, metadata dependencies and canonical artifact digests. Its artifacts have unique safe relative names, never destination paths. A hit copies canonical bytes into an output-sibling staging directory — not cache or compiler-input staging — then replaces the **entire `outDir`**, including stale or unrelated files; it is not a merge or a fast return trusting the published tree. External-file temps and leftover output staging are cleaned independently after success or failure.
- `preparePublication` rewrites relocated imports before committing output. External `outFile` destinations get prepared temporary files; the original staged entry is removed from the published tree/list, not from canonical cached bytes. Both fresh and cached paths use the same preparation and commit logic.

Boundary checks run through [`validateOutputPathBoundaries`](../../src/build/resolve/options.ts) before destructive publication and again after resolution adds known inputs. Native emit retains dependency paths in nonpersistent builds and content snapshots in persistent builds; publication must project paths from either representation without weakening protection. If adding outputs, manifests, or sidecars, trace their paths through staging, [`persist.ts`](../../src/build/cache/final/persist.ts), restoration validation, and returned `outputFiles`. For Vite publication, continue through [`stageCompiledCoreOutputs`](../../src/vite/workspace.ts) and [`plugin-compile/emit`](../../src/vite/plugin-compile/emit): core staging is followed by adapter naming/asset rewriting and emission, not shipped directly unchanged.

### Follow resource acquisition through failure

[`createCacheStore`](../../src/shared/cache-store.ts) unwinds partial temporary-root acquisition. The pipeline takes ownership before resolution, so a missing `tsconfig.json` no longer depends on a returned `ResolvedBuild` for cleanup. Normalization, setup, compilation and publication share the failure boundary. Staging, cache-store disposal and lock release are all attempted; aggregate errors retain primary and cleanup diagnostics in `BuildFailure`. A cleanup error can turn a published success into a failure result.

The same cache-store owner serializes mutable project state and `cleanCache`. An inactive owner or sufficiently old unidentified lock fails closed with an exact-path manual recovery diagnostic; no contender steals/deletes it. Lock release checks the ownership token. [`src/shared/files.ts`](../../src/shared/files.ts) validates the complete staged destination set before sweeping; it permits symlinked ancestors but rejects the selected root and expected inner/leaf symlink escapes. That boundary is not a concurrent hostile-filesystem sandbox.

Follow [`src/shared/concurrency.ts`](../../src/shared/concurrency.ts) wherever staged writes, file snapshot hashes or compiler jobs are concurrent: the first rejection stops admission, active work drains before rejection, and only then may owners dispose resources or release locks. [`driver/resident.ts`](../../src/build/closure/driver/resident.ts) similarly waits for termination, with escalation, before fallback compilation. [`compiler/run.ts`](../../src/build/closure/compiler/run.ts) waits for fallback process/stream closure; retained diagnostics belong to the final attempt.

### Select the proof

- Publication failure: `failed Closure builds preserve the last published output` in [`test/build/cache-safety.test.mjs`](../../test/build/cache-safety.test.mjs) first publishes good output, then forces a real compiler failure and compares the old output. Nested manifest restoration is covered by `safe nested manifest paths survive publication and cache restore` in the same file. Both use rebuilt `dist/`, native, and Closure.
- Relocation: `off-mode outFile publishes outside outDir and rewrites shared imports` in [`test/build/workspace.test.mjs`](../../test/build/workspace.test.mjs) imports source, but still invokes native and Closure. It checks the original entry is absent and executes both relocated and non-relocated entries against the shared state.
- Setup/cleanup: `failed resolution cleans acquired off and temporary workspaces`, `cleanup failure retains the primary build diagnostic`, and the partial-acquisition cases in [`test/build/workspace.test.mjs`](../../test/build/workspace.test.mjs) import source and exercise failures before Closure. The same file's failed-Closure/lock-release case and relocation case require the real native/compiler lane.
- Cache coherence: `metadata preparation failures preserve previously published output`, `fresh resolution notices a newly added higher-priority source`, `inherited compiler config changes invalidate final artifacts`, `restoration leaves canonical cached artifacts immutable and replaces stale output`, and `failed restoration cleans leftover output staging and external temps` in [`test/build/cache-safety.test.mjs`](../../test/build/cache-safety.test.mjs) exercise rebuilt `dist/`, native and Closure. These distinguish preparation, fresh resolution and restoration from merely successful compilation.
- Lock/file boundaries: the acquisition and stale-unidentified-lock cases in [`test/build/cache-correctness.test.mjs`](../../test/build/cache-correctness.test.mjs), plus selected-root/ancestor/leaf symlink and invalid-destination-set cases in [`test/shared/files.test.mjs`](../../test/shared/files.test.mjs), exercise source filesystem behavior without real Closure.
- Drain/process lifetime: [`test/build/concurrency.test.mjs`](../../test/build/concurrency.test.mjs) checks stop-admission, draining and result ordering; `resident failure waits for delayed child termination before returning fallback capability` in [`test/build/closure-lifecycle.test.mjs`](../../test/build/closure-lifecycle.test.mjs) uses an isolated child-process fixture. Update lifecycle ownership, metadata schemas/validators and restoration together when changing an artifact's lifetime. Keep [delivery invariants](architecture.md#delivery-invariants) and the [API cache/output contract](../reference/api.md) aligned with the actual failure boundary; do not turn the per-directory rename mechanism into an all-or-nothing guarantee.

## Closure and native compiler upgrades

### Follow the compiler boundary in both directions

1. Closure's current pin (`20260909.0.0`) is in [`package.json`](../../package.json); Oxc-family pins (`0.150.0`, requiring Rust 1.96+) are in [`native/Cargo.toml`](../../native/Cargo.toml). Update corresponding lockfiles with dependency changes. Keep the Oxc family aligned as its manifest specifies; successful Rust compilation is not evidence that lowering semantics survived. TypeScript 7 CLI/declaration tooling and vendor TypeScript 6 runtime API are separate dependencies, not competing loader alternatives.
2. [`native/src/closure_capabilities.rs`](../../native/src/closure_capabilities.rs) owns the declared syntax capabilities. Current direct parser measurements are private elements false, static blocks true, and top-level await false; `es2021` remains the prebundle target. Consumers include [`transpile/lowering/mod.rs`](../../native/src/transpile/lowering/mod.rs), [`graph/deps.rs`](../../native/src/graph/deps.rs) and [`graph/resolve.rs`](../../native/src/graph/resolve.rs), plus the JS [`closureCompilerCapabilities`](../../src/native/load/wrappers.ts) wrapper consumed by [`Vite prebundling`](../../src/vite/prebundle/orchestrate/bundles.ts). The await classifier includes module-level `await`, `for await` and `await using`, excluding nested functions/arrows. Parser acceptance, prebundle target and runtime preservation are separate decisions; do not report pending runtime gates as passing from this table.
3. [`compiler/run.ts`](../../src/build/closure/compiler/run.ts) first tries the [resident driver](../../src/build/closure/driver/resident.ts) unless disabled, then uses the installed compiler implementation. The fallback can use the compiler package's native image or Java jar. That native image is **not** this project's Rust addon. [`platform-externs/archive.ts`](../../src/build/closure/platform-externs/archive.ts) separately locates the jar whose externs are sliced. Keep parser, driver, compiler options, and extern-archive behavior in view when changing the dependency.
4. For Rust/JS boundary changes, pair [`src/native/abi.ts`](../../src/native/abi.ts), [`load/transpile.ts`](../../src/native/load/transpile.ts) or [`load/wrappers.ts`](../../src/native/load/wrappers.ts), and the corresponding [`native/src/lib.rs`](../../native/src/lib.rs)/Rust input definitions. Chunk planning and transpilation take owned object inputs; graph resolution retains its six positional arguments. Explicitly reconstructed boundary objects protect field names through the package's self-build. Rust uses snake_case with explicit N-API `js_name` attributes, and separate Serde renames wherever persisted camelCase data must remain unchanged. Optional N-API strings use `undefined`, not `null`. Rebuild the addon and JavaScript together after an ABI change. For chunk changes, `split` and `bundler-runtime` fold into the same native emission shape in [`closure_jobs.rs`](../../native/src/closure_jobs.rs); do not introduce fixes for just one public spelling by treating them as separate native backends.

Cache identity is part of the upgrade route: [`getPackageSignature`](../../src/build/resolve/signatures.ts) sees package metadata and the local addon, while [`runPreparedClosureJob`](../../src/build/closure/compile-jobs/index.ts) passes the compiler tag and effective job to the job cache. The tag returned by `resolveClosureCompilerVersionTag` is a resolved jar/native path (or fallback string), not a hash of compiler bytes. Replacing a binary in place is not evidence of a new cache identity. Use cold and warm consumer builds when investigating an upgrade.

## Vite rebuilds, provenance and output ownership

Follow [`plugin/index.ts`](../../src/vite/plugin/index.ts) from reusable transform captures into a fresh `generateBundle` output map. Watch-mode reuse must retain unchanged transformed modules, drop vanished module IDs, and never carry rendered-length evidence or shaking mutations into the next output. Parsed sources belong to their capture records, not a process-global map; rewritten code invalidates that revision and metrics belong to the build that requests analysis. Materialization and static-member annotation consume the same record and JavaScript parser policy for transformed text. [`plugin-graph/prepare.ts`](../../src/vite/plugin-graph/prepare.ts) owns retained-graph selection and settled prebundling; extern generation consumes the settled graph, while metadata retains the prebundle source graph for provenance.

Declaration overlay changes belong in [`collect/overlay.ts`](../../src/vite/type-metadata/collect/overlay.ts) and [`export-graphs`](../../src/vite/type-metadata/export-graphs): reads and parse facts are collection-owned and lazy. Keep consumed-file invalidation, source-graph membership and settled-graph protocol dependencies separate; do not restore eager reads of the whole provenance tree.

[`resolveDeclarationOverlays`](../../src/vite/type-metadata/declaration-overlay/index.ts) batches entries with equal compiler options, resolution mode and project root. Pure-module groups share one program/checker. Globals and module augmentations, including automatic ambient types, require isolated entry checkers; a group-local compiler host still shares library reads and parsing. Do not turn that host into a process-global cache or let one entry's augmentation leak into another. Shared dependency unions invalidate the collection conservatively; app-tsconfig Bundler analysis remains separate.

Authored-only materialized graphs bypass dependency classification, import parsing and rewriting. The guard checks normalized membership of every module, not equal collection sizes. It still uses ordinary graph staging when the runtime source directory differs, preserving one-to-one provenance and caller-owned source files.

[`plugin-compile/compile.ts`](../../src/vite/plugin-compile/compile.ts) passes `authoredFiles` as invocation values and a separate runtime source-map output path. Follow those through normalization, signatures and [`emit.ts`](../../src/build/transpile/emit.ts), rather than introducing a JSON membership file or global memo. **The delivered metadata branch still bypasses standalone semantic preflight.** An authored-membership fix does not prove Vite rejects all original-source TypeScript errors.

[`workspace.ts`](../../src/vite/workspace.ts) owns stable capture locks and temporary disposal through emission; debug mode owns only `<debugDir>/gcc-ts-bundler`. With persistent caching, core publication uses an invocation-owned external temporary output root, never the cache tree containing captured compiler inputs. Disposal attempts that root and the capture resources independently before releasing the lock. External output-directory identities collapse to `..` in the options key, so a fresh destination does not itself defeat canonical reuse. Adapter final staging still belongs to the capture workspace.

Final adapter naming/asset rewrites happen after core output staging and before final minification. [`emit/rename.ts`](../../src/vite/plugin-compile/emit/rename.ts) owns initial manifest/source-map loading and the reusable identity joins. Later passes share the mutable manifest instead of rereading it; source-map validation and the native sidecar artifact remain mandatory. Preserve both naming passes around asset URL resolution. For Vite 8 emitted-file URLs, follow [`plugin-graph/normalize.ts`](../../src/vite/plugin-graph/normalize.ts) into [`output/asset-urls.ts`](../../src/vite/output/asset-urls.ts): canonical placeholders cross Closure, but current output reference/URL IDs stay host-owned. After chunk placement, re-enter the host's `resolveFileUrl` hook with its public ABI keys intact; do not copy a URL rendered for an obsolete chunk location. Missing host ownership/resolution fails closed. A change to capture cleanup must not delete caller-owned debug files or preserve stale per-output evidence.

Useful proofs in [`test/vite/plugin.test.mjs`](../../test/vite/plugin.test.mjs) include `one Vite watcher recovers from worker rejection with current imports and exports` for real rebuild/recovery behavior, `Vite debug workspace cleanup preserves caller-owned directory contents` for source filesystem ownership, and `esm chunk naming hashes every chunk and rewrites import specifiers` for delivery naming. The watcher uses the built plugin and real native/Closure compilation. `emitted file URLs preserve underscores inside opaque host reference ids` exercises source placeholder/host-hook handling and evaluates the resulting URLs; `gccTsBundler resolves Vite asset and public placeholders before final output hashing` covers the built integration. `native preflight uses current authored membership on repeated analysis` in [`test/vite/type-metadata.test.mjs`](../../test/vite/type-metadata.test.mjs) exercises source analysis; it is not a semantic-preflight proof for the delivered-metadata branch. Use a real Vite fixture for a changed extern/prebundle route, not a generator-only output comparison.

## Build tooling, package publication and preview helpers

### Follow the exact artifact

- Bootstrap JavaScript belongs to [`build-js.mjs`](../../scripts/build-js.mjs); public declarations belong to [`bundle-declarations.mjs`](../../scripts/bundle-declarations.mjs), with one TypeScript 7 emit followed by independent Rolldown declaration bundles. [`run-typescript.mjs`](../../scripts/run-typescript.mjs) locates the CLI via the package manifest. The vendor TypeScript 6 API remains the runtime analysis dependency.
- [`build-self.mjs`](../../scripts/build-self.mjs) creates temporary stage 0, complete boundary/public externs, stage 1 and optional stage 2 before publishing stage 1. A declaration-entry change must reach manifest exports, bootstrap entries, bundled public declarations and the self-build's stage-copy/extern checks.
- [`prepare-release.mjs`](../../scripts/prepare-release.mjs) validates coordinated target metadata, runs hygiene and a cache-off stage-2 build, then packs each payload once. [`verify-package.mjs`](../../scripts/verify-package.mjs) consumes those exact root/host-native archives; [`publish-npm.mjs`](../../scripts/publish-npm.mjs) digest-checks the complete set before uploads and each archive immediately before its own upload. [`prepublish-guard.mjs`](../../scripts/prepublish-guard.mjs) rejects direct directory publication. Never move a rebuild or repack after verification.
- [`native-targets.mjs`](../../scripts/native-targets.mjs) is shared authority, not caller-supplied platform metadata. Match changes in the builder, release runner matrix, optional-dependency manifest and package consumer. Native artifacts for all targets are checked structurally, but runtime consumer proof remains host-only.

Select `release publishes the exact verified archive without rebuilding or repacking the mutated tree`, preparation-failure cases, and dry-run/direct-publication cases in [`test/package/release.test.mjs`](../../test/package/release.test.mjs). These isolated script fixtures defend upload order and payload identity without performing a real npm release; they do not replace real package/self-build gates. [`test/native/build-native.test.mjs`](../../test/native/build-native.test.mjs) checks rejected selectors before toolchain/filesystem side effects, supported metadata/version matching, and musl flag behavior. For actual artifacts, use the [workflow lanes](workflows.md#native-packaging-and-releases), not invented test commands.

### Keep preview separate from build

[`preview-example.mjs`](../../scripts/preview-example.mjs) resolves one exact or unambiguous-prefix example, requires existing output, and launches that example's installed Vite on loopback with strict-port behavior. It never builds or evicts an existing listener. Follow selection/argument validation through child creation, exit status and signal forwarding; unrelated processes are not owned resources.

[`test/package/preview.test.mjs`](../../test/package/preview.test.mjs) exercises ambiguous/invalid selection without a child, occupied-port failure while an unrelated listener survives, and loopback/interruption behavior. These subprocess fixtures do not prove the selected application's browser behavior. [`verify-example-dists.mjs`](../../scripts/verify-example-dists.mjs) separately uses system Bun and frozen example locks for fresh-byte comparison; it does not supply preview output implicitly. Commands and their prerequisites stay in [Workflows](workflows.md#build-and-preview-an-example).
